# Brilliant 设计与 HTML Audio 播放

## 设计基准

AI 与人工协作统一参考 [AI 设计规范](AI-DESIGN.md) 和根目录 [AGENTS.md](../AGENTS.md)。

Brilliant 项目：brilliant-cloud://witty-jaguar/share-music。
- 01–04 房间与播放器：一起听、发现、创建、队列。
- 05 登录 / 06 注册：用户名与密码认证。
- 07 搜索歌曲：点歌搜索。
- 08 API与播放实现：本次新增的实现范围与后端约束。

实现保留 Vue / Pinia / Router，不引入第二套 UI 框架。tone.css 在现有组件样式及响应式样式之后加载；蓝色 #4F80DB、蓝到奶油渐变、浅色半透明卡片、桌面顶部导航，窄屏使用当前顶部双层导航与底部全局播放器。不存在真实 API 的推荐内容、头像编辑、房主审批、喜欢等不伪装成功。

## 当前 API 对照

- POST /api/login：name/password/register，不采集邮箱。
- GET /api/rooms?keywords=&category=：房间搜索、分类，列表人数来自后端。
- POST /api/rooms：名称、描述、氛围、可见范围。
- GET /api/rooms/resolve/:code：12 位房间码解析后 WebSocket join。
- PUT /api/rooms/:id/settings：完整设置和 expectedStateVersion；冲突提示用户，不无限重试。
- 网易云 / QQ 音乐搜索与 music/uploaded：搜索点歌和共享音乐库，requestId 幂等。
- /music/:trackId 与 refresh=1：返回直链、稳定缓存键和大小；遇到 403 等失效时静默强刷并重试一次，不弹续链提示。
- /music/:trackId/audio：浏览器 Bearer 鉴权代理；客户端只检查大小，不计算音频摘要。

## 播放边界

CloudPlayer 唯一控制 HTMLAudioElement，由系统 WebView 解码。Rust 保持原有缓存目录、命名、原子写入与并发去重，下载前后仅检查大小与边界、不计算或比较音频摘要。HTML Audio、波形分析与内嵌封面使用同一 Blob。

ready 必须等待目标位置 seek 完成并 buffered；服务器提交后依据共享时间轴播放/暂停/纠偏。退出房间、切歌或过时下载会清理或释放 Blob。本地音量不改变房间音量。Windows 系统媒体按键继续调用房间指令，不创建原生播放器。Windows 任务栏悬停缩略图显示当前封面，优先复用内嵌图片，保留控制按钮；暂停保留封面，切歌清旧，停止、断线和离房恢复普通窗口预览，加载失败使用默认唱片图。封面由独立隐藏的任务栏预览代理提供，Peek 委托真实主窗口，Alt+Tab 保留主窗口真实画面，不使用封面替代。代理不出现在 Alt+Tab，点击/关闭转交主窗口，隐藏到托盘注销代理；注册或位图失败回退系统窗口预览。

真实播放需服务端、在线房间成员与对应音源的有效登录与完整歌曲权限；测试中的模拟界面不代表真实联调成功。

GlobalPlayer.vue 在发现、房间与我的音乐页面底部持续显示。唯一 HTML Audio 实例仍由 bridge / CloudPlayer 控制，切路由不重新创建音源。本地音量、进度预览、权限和 pending 锁均保留。

发现页主视觉与卡片列表使用正常文档流的 flex 布局：按钮下方保留留白，封面不可被压缩，短窗口使用紧凑间距而非裁切内容。房间卡片本身为原生按钮，点击或按 Enter / Space 加入。断线、房间已满、正在加入时禁用相应操作，保留状态反馈。

“相似推荐”区域通过当前歌曲网易云 ID 调用后端 `simi_song`，展示最多 3 首未在队列中的推荐歌曲。切歌取消旧请求，普通状态同步不重复加载；无播放、无来源 ID、推荐为空或接口失败时展示真实状态，不使用待播列表充当推荐。点击歌曲只加入队列，不自动切歌，沿用后端权限和幂等请求。收藏未开放时禁用；播放模式已接入房间服务端，支持点歌、无放回随机、单曲循环和列表循环，不使用本地 Audio.loop 冒充房间同步。

当前 Brilliant 文件未提供独立“我的音乐”、音乐库、成员权限、更新日志画板；这些界面复用原稿的顶部导航、渐变、卡片、按钮与列表系统，不宣称像素级对应不存在的画板。

原稿插画直接从 Brilliant 导出：登录唱机 / 默认专辑为 SVG；房间唱机与发现页唱片用 PNG 保留渲染器的金属刻纹与效果，避免 SVG 导出丢失描边。没有额外在线字体或图片请求。

弹层共享带引用计数的背景锁，队列切换搜索时不提前解除 inert，也不会在关闭搜索后永久锁住页面。键盘焦点、Esc、Tab 和滚动恢复保持可用。

播放列表使用紧凑头尾布局，列表 flex 占满剩余空间。双击歌曲行沿用房间命令播放该曲；当前曲暂停时继续，已在播放时不重置进度。手柄/菜单双击和拖动结束后的保护期不触发播放，断线、无权限、同步过渡及未确认操作时禁止触发，保留单独播放按钮。拖拽仅操作手柄（支持 Pointer Events 鼠标/触摸），松手后通过既有 `reorder` 命令发送完整歌曲 ID 顺序，不重置当前播放或进度；房主与拥有播放列表控制权限的成员可排序，断线、同步过渡和未确认操作期间禁用。房间状态版本变化、关闭抽屉、指针取消时撤销拖拽并停止自动滚动，避免覆盖新队列；服务端仍负责权限和状态版本校验。

页面几何自适应由 `adaptive-layout.css` 负责（其后还加载下拉框样式 selects.css），而不是全局隐藏滚动条。桌面窗口（宽度超过 900px、高度至少 640px）按实际视口分配导航、播放器和主内容空间；舞台、歌词和聊天伸缩，发现房间、歌单和歌曲列表在内部滚动。搜索弹层同样使用可伸缩结果区。登录/注册按窗口高度伸缩，短窗口缩减留白和插画尺寸。窄屏、极短窗口、长文案和高缩放保留必要滚动，不裁切控件；新增内部列表可聚焦，支持键盘滚动。


## 生产模型与 Mac 音频兼容

生产桌面 CSP 与 Vite preview 共用配置：除了 img-src blob:，还必须有 connect-src blob:，因为 GLTFLoader 会通过 fetch 读取 GLB 内嵌贴图。缺失时模型几何仍显示，但法线/金属度等纹理可能丢失，不能误判成 Vite 压缩关闭着色器。两种构建均保留相同 ACES/Alpha 管线；渲染 canvas 的 data-stage-pipeline 标记可核对管线、档位及 MSAA。

所有 Mac（含 Intel 与 Apple Silicon）默认使用音频优先档：1.5×原生 devicePixelRatio 超采样，不另设像素预算/像素比上限，仅保留GPU尺寸限制；MSAA最高2×（不支持时降为仅SMAA）、SMAA HIGH、60fps上限而非30fps、1024阴影；保留 ACES、透明边缘和金属环境反射，实时频谱暂停。非 Mac 保留原高画质档。两种模型复用房间缓存激活状态和页面 visibilitychange，隐藏时暂停绘制及 iPod 屏幕计时器，恢复不重建模型或抢占音乐输出；iPod 插值使用帧间隔保持动画响应速度。此策略不改变歌曲下载校验、权限或共享时间轴，不保证解决外设、系统、驱动或网络导致的所有故障，最终需在目标Mac上复测模型流畅度和声音连续性。

舞台原状态文案区域不渲染文字或动态占位行，准备状态不再改变舞台布局；音频错误使用固定 notice。模式入口复用现有图标按钮和播放列表原生下拉框。

“我的音乐”使用网易云歌单／已收藏两个分类，个人主页显示可访问的用户歌单，歌单和专辑直接显示详情与入队操作；应用内收藏按同频账号保存，不改变网易云收藏。2026-11-05 在原 Brilliant 项目新增独立设计页 `09 我的音乐 · 简洁高效.bl`，包括列表、详情、小窗口、窄屏与收藏空数据占位，客户端已应用新版布局；已收藏为空时不展示状态说明板块。详情保留次级立即播放，将全选文案按实际追加加载行为改为“全选已加载”；复用 AlbumArt、原生按钮、现有接口和内部滚动，不引入设计示例数据。实现与验证边界见 [我的音乐设计交付](MY-MUSIC-DESIGN.md)，实际发布状态以 GitHub Release 为准。
