# 发布验收操作

## 原生与平台

在 Windows 10/11、macOS 13+、PipeWire Linux 分别编译和运行。逐个选择输出设备，测试采集授权拒绝、设备拔出、采集停止及退出释放。确认推流者房间输出关闭，防止反馈。非支持规格须明确拒绝。

用 44.1/48/88.2/96kHz × 16/24bit 双声道文件比对编码前与接收解码 PCM。无损模式不允许持续重采样或变速；MP3/AAC 保持原始有损标识。校验错误、缓冲溢出与缺块须有明确错误记录。

## 同步与控制

8 台真实设备播放 30 分钟。每秒采样客户端媒体时钟，统计同一服务器时间的最大/最小进度差，保存原始数据与 P50/P95/P99；目标 P95 ≤100ms。另用共同录音或测量设备检查实际声学输出，不能用 UI 进度替代。

测试连续拖动、同时切歌、暂停/恢复、切换音质、中途加入。切换未完成时应拒绝重叠操作；重试必须使用新快照，不能自动重放过期意图。

断开提供者、控制连接和房主：验证缓存耗尽处理、直播停止恢复列表、15 秒断控停止、60 秒房主移交、重新连接后的代次丢弃。重启服务应恢复配置且停止播放。

## 权限与容量

对四个权限分别授权和撤销，直接向 WebSocket 发送绕过 UI 的请求；测试普通成员覆盖、房主权限、即时文件/直播所需组合授权，以及列表轮播无需推流权限。

开启至少 3 个房间、总计 24 个控制连接。不得超过每房间 8 人。在线数与媒体并发容量分别统计，记录服务器 CPU、RSS、控制往返和音源上行。

## 公网与 5Mbps

使用不同运营商和 NAT 类型验证直连、TURN UDP/TCP、穿透失败、中继预算耗尽。至少连续播放 30 分钟覆盖多次凭证续期，检查重连缓冲与资源释放。

在测试服务器查看网卡和已有 qdisc，再运行整形脚本的预览；确认后由部署者执行 `--apply`。用服务器接口计数器和流量工具测量全出口 ≤5Mbps、TURN ≤3.5Mbps，分别记录 IPv4/IPv6、容器路径与运营商流量计算口径。

注入限速、丢包、抖动和断网，确认持续不足时提示等待或拒绝媒体，不无限堆积内存，不静默转成 Opus。所有成员应看见房间音质切换。

## 结果归档

保存：代码版本、系统/音频设备、NAT、媒体规格、参与者数量、时长、原始时钟数据、出口流量、CPU/RSS、异常日志及通过/失败项。失败项修复后重测，生产发布前补齐测试报告中的差异与未验收项。
