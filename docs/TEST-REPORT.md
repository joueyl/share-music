## 与原方案的实施差异

1. 当前文件媒体采用按时间定位的独立 FLAC 块缓存，不下载完整原文件，也未实现原文件块级断点续传、下一曲完整预传输及跨音源持久缓存。当前曲掉线后可使用已有内存 PCM，耗尽时恢复列表。
2. 缓冲采用 3 秒准备、2 秒最低启动及 5 秒预取窗口；尚未实现基于抖动统计在 2–5 秒间自适应调节的控制器。
3. 当前 DataChannel 的预取低优先级通过独立通道和连接缓冲限制实现；还没有完整的全局带宽公平调度器。链路探测为短时样本，尚未实现提供者上行的全房间持续容量估计。
4. 为避免低估重编码后的流量，文件准入保守使用解码 PCM 码率。实际 FLAC 通常低于该值，但当前不会据此放宽中继准入。Opus 编码目标为 192kbps，独立块补偿按 230.4kbps 预算。
5. TURN 短期凭证通过定期重建连接续期，可能重新缓冲；公网持续性需要验收。
6. 提供者重连后的路径缓存仍在客户端内存；应用重启后须重新导入文件。服务端不保存或自动恢复本地路径。
7. 已提供三平台采集源码，但只完成 Windows 编译。macOS/Linux 编译和设备授权、热拔插、音频反馈需对应环境验证。
8. 当前交付为开发预览，不含签名安装包、自动更新或三平台发布产物；没有部署到远程服务器。

因此当前版本是可运行的开发原型，不能作为“全部生产验收完成”的声明。

## 2026-10-09 静音恢复修复

## 2026-10-09 公共 TURN 接入

增加 Metered REST 与固定凭证接入；API Key 仅服务端保存，外部预算独立于 5Mbps 自建出口。类型检查、前端构建和 28 项 TypeScript 测试通过，其中真实 WebSocket 测试验证外部中继授权、UDP/TCP/TLS 配置下发及独立容量统计。Metered API 使用测试响应验证缓存、失败恢复与密钥保护；尚未提供真实账号凭证，因此未执行公网 TURN 收听测试。

## 2026-10-09 多 STUN

加入 stun:stun.miwifi.com:3478 与 stun:39.107.142.158:3478，支持 STUN_URLS 多地址及兼容旧 STUN_URL。类型检查和 29 项测试通过；本机对两个地址的 UDP Binding 探测均验证有效 STUN 响应。

## 2026-10-09 STUN 失败提示

Rust 控制层独立异步执行 UDP STUN Binding 诊断（每地址 4 秒，IPv4/IPv6 并发候选），周期 60 秒；房间显示部分/全部失败及 DNS、UDP 请求或超时原因。诊断失败不等同于 ICE 失败，不停止已有播放。新增本地模拟成功、事务不匹配和超时验证，Rust 核心 9 项测试通过；Vue 类型检查和构建通过。

## 2026-10-09 退出房间停止播放

旧 Stop 保留房间快照，后续旧信令可能再次 reconcile 播放链路；服务端离开时也可能向该连接发布最后一份房间快照。现在停止时清除快照、输出位置、管线和缓存；Connection 同步清除希望加入的房间并停止媒体，过滤退出后的快照、信令和中继回复，断网退出不依赖 WebSocket，并且重连不会重新加入。前端丢弃退出后的房间/播放事件并清空媒体状态；服务端在发布离开变化前解除连接的房间关联。

38 项 TypeScript 测试、12 项 Rust 单元测试、类型检查、桌面 cargo check 均通过。真实 NestJS 内存服务、两个 Rust 客户端、合成 WAV 与 SDL dummy 输出集成测试通过（27.40 秒），覆盖播放、静音恢复、暂停、seek、Opus、成员退出后不恢复播放、房主继续播放、重新加入恢复和房主退出；未采集用户音频。Windows 安装包重新生成，当前校验值以同目录 `.exe.sha256` 为准。
