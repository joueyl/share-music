# 手机网页适配

手机与窄屏样式由 `apps/client/src/responsive.css`、`tone.css`、`brilliant.css` 和 `adaptive-layout.css` 共同控制，加载顺序见 [AI 设计规范](AI-DESIGN.md)。桌面使用顶部导航与底部全局播放器；窄屏采用顶部双层导航，播放器位于底部，内容按可用宽高伸缩。

## 交互调整

- 登录页、房间发现、播放页、歌单页及所有弹窗使用可收缩布局，不通过隐藏整页横向溢出来掩盖问题。
- 底部全局播放器预留页面滚动空间及 safe-area-inset-bottom；顶部、页面边距和登录页适配安全区。
- 使用动态视口高度限制弹窗，短屏时允许弹窗及内容区域滚动；输入字号至少 16px，保留浏览器双指缩放。
- 手机主要按钮至少 44px 高，播放按钮 52px，图标操作按钮 44×44px。音量与播放按钮分行，列表操作成组换行。
- 长房间名、歌单名最多显示两行；歌曲名使用省略显示，歌单名保留 title 与完整 DOM 文本，避免撑宽页面。
- 搜索输入、结果及添加按钮、歌单批量操作、聊天和更新日志均使用窄屏排版，桌面功能及权限判断不变。

## 本地核验

使用浏览器视口仿真检查 320×568、375×812、390×844、430×932、768×1024 触屏、844×390 横屏和 1280×800 桌面；同时用 390×360 短屏检查搜索、音乐库和更新日志弹窗。测试数据包含长名称、长聊天链接和多操作按钮。

核验时记录页面宽度、弹窗边界、按钮尺寸及实际截图。视口仿真不是 iOS Safari、Android 浏览器或实体刘海设备的实机验收；软键盘和真实安全区仍建议在目标设备检查。

本次是 Web 响应式布局，不生成 Android/iOS 原生安装包。不改变开发服务器默认的本机回环监听地址；手机访问应使用已部署的 HTTPS 网页，或由开发者另行明确配置可访问的局域网调试环境。
