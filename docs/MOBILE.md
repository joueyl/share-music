# 手机网页兼容与 APK 独立界面

手机与窄屏样式由 `apps/client/src/responsive.css`、`tone.css`、`brilliant.css` 和 `adaptive-layout.css` 共同控制，加载顺序见 [AI 设计规范](AI-DESIGN.md)。桌面使用顶部导航与底部全局播放器；移动断点为宽度 ≤720px，或宽度 ≤900px 且使用 coarse 指针。该区间采用 Brilliant 手机稿的顶部单层栏、底部三项导航和紧凑播放器，非移动区间保留既有布局。

## APK 独立入口

APK 不再加载本文件下述的桌面/网页兼容样式；使用 `apk.html` → `src/apk/main.ts` → `ApkApp.vue`、`apk/pages/` 及 `apk.css`。界面按 Brilliant 手机稿实现，宽高决定单栏、短横屏或展开双栏，不以 UA 或桌面窗口宽度决定入口。认证/房间/音乐库/播放与桌面共享 `src/features/` 和既有 store/bridge/CloudPlayer；搜索、队列、成员、聊天等复杂交互复用同一组件及焦点锁。

构建与 Actions 说明见 [Android APK](ANDROID-APK.md)。常规 `index.html` 仍使用桌面入口及以下兼容样式，两个输出互不覆盖。APK 前端构建拒绝引入桌面根页面与布局样式，避免“APK 又打进桌面入口”。

APK 提供可选“记住密码，下次自动登录”，由 Android 原生安全存储保存；手机浏览器不启用应用自行保存密码，可使用浏览器/系统密码管理器，见[安全记住密码](SAVED-LOGIN.md)。

## 网页兼容交互调整

- 登录页、房间发现、播放页、歌单页及所有弹窗使用可收缩布局，不通过隐藏整页横向溢出来掩盖问题。
- 底部全局播放器预留页面滚动空间及 safe-area-inset-bottom；顶部、页面边距和登录页适配安全区。
- 使用动态视口高度限制弹窗，短屏时允许弹窗及内容区域滚动；输入字号至少 16px，保留浏览器双指缩放。
- 移动主要操作和图标按钮采用至少 44px 命中区。全局播放器默认显示摘要、收藏、播放/暂停、队列与展开按钮；展开后显示同一组上一首、下一首、停止、播放模式、进度和本地音量，不创建第二个 Audio。展开高度同步预留给页面，打开共享弹层或换房时收起；弹窗期间仅按原规则允许队列切换。
- 长房间名、歌单名最多显示两行；歌曲名使用省略显示，歌单名保留 title 与完整 DOM 文本，避免撑宽页面。
- 搜索输入、结果及添加按钮、歌单批量操作、聊天和更新日志均使用窄屏排版，桌面功能及权限判断不变。

- 发现页使用横向紧凑房间卡片、始终可用的房间搜索和横向分类，人数/容量来自真实列表；初次读取失败与真正空列表分开，刷新失败不丢弃上次成功结果。
- 手机竖屏模型置于歌曲和歌词上方；低于 500px 高的移动横屏恢复左右布局，保留真实滚动、3D 模式、当前歌曲、歌词和路由缓存。
- 队列改为底部面板，搜索为全屏渐变页，创建/设置与成员面板采用渐变全高表单。复用原有焦点管理、Esc、背景锁和关闭恢复，不生成画板中的系统状态栏、虚构键盘或操作回执。
- 我的音乐保留实际的音乐主页/已收藏及单曲/歌单分类，使用蓝色分段控件、半透明资料/详情/空态卡片、两列封面网格；不照搬没有对应接口的画板示例分类。

## Brilliant 移动端设计稿（2026-11-18）

APK 发现首页按设计稿去除“找到你的同频”营销板块及占位，品牌栏之后依次为创建房间/房间码、搜索、分类及房间列表。首页使用独立于其它紧凑页面的留白和卡片尺寸；底部播放器与导航不变。

### APK 房间页：大唱片与下沉控制

APK 手机“一起听”按 Brilliant 主稿布局：唱片、上方唱臂、圆形唱片标签与下沉播放控制；收藏、聊天靠近歌曲信息，歌词、成员、设置位于辅助行。保留共享底部导航和 44px 次级触控区；599px 及以下用 48px 主播放按钮与紧凑唱片，宽屏及短横屏分别保留各自的控制尺寸。房间外的迷你条仅保留当前歌曲封面与歌名、播放/暂停及共享播放列表，不显示播放状态文字，并复用同一播放控制与权限。

五种尺寸设计共用 `ImmersiveVinylArtwork`；客户端采用真实专辑封面，无封面使用现有占位图。宽屏保留歌词与聊天，短横屏以可用大小排列舞台和控制区，空间不足允许内部滚动。仍可通过「设置」切换 3D 唱机、iPod 和流光歌词。桌面及网页兼容入口未改，未发布新安装包。

设计位于原项目 `brilliant-cloud://witty-jaguar/share-music` 的“移动端”目录，不替换原桌面画板：

新增设计沿用蓝色主操作、蓝到奶油渐变和半透明圆角卡片；歌单详情、绑定及状态页引用现有 MiniPlayer / MobileNavigation 实例。断线示例的播放器控制为灰态，示例歌曲与成员不作为实际数据来源。创建页保留 80 字名称上限、四种氛围、两种可见性及当前默认权限；入队与立即播放分开，绑定不代表音源登录。

**实现边界：**网页兼容界面及 APK 独立界面已应用上述移动视觉和底部导航，复用原组件、store、bridge、权限及服务器确认链路；桌面不改主题，不改变播放协议、缓存或服务端 API。状态界面根据现有请求状态渲染，不将静态画板作为运行时页面。APK 已按 ≥760px 宽、≥600px 高提供播放/聊天双栏，但实体折叠屏铰链、分屏及软键盘未实机验收；网页兼容区间仍按可用宽高响应，不声明逐像素还原。

## 本次核验（隔离浏览器仿真）

- 使用本机 Vite 与内存注入的测试账号/房间/接口响应检查布局，没有登录真实账号或提交生产操作。390×844 检查认证、发现长列表、我的音乐及 18 首长歌单末尾、播放舞台、队列、搜索和设置；320×568 检查设置滚动及队列末尾，844×390 检查搜索滚动与横屏舞台；390×360 检查聊天输入区可滚动到播放器上方。
- 1024×640、1280×720、1440×960 检查房间、桌面播放器及导航：移动导航隐藏，模型与歌词仍左右排列，文档宽度与视口一致。
- 390×844 下紧凑播放器/导航各 72px，展开播放器通常为 228px，极短屏按剩余空间限高并内部滚动，同时相应增加内容预留；检查展开控制的 44px 按钮、队列内部滚动、共享背景 inert 锁与队列切换搜索后解锁。
- 真实软键盘、iOS Safari/Android WebView、安全区实体设备、高缩放、安装包及真实音频连续性未验收；“减少动态效果”使用浏览器仿真，不能代替全状态实机验证。

## 客户端核验要求

使用浏览器视口仿真检查 320×568、375×812、390×844、430×932、768×1024 触屏、844×390 横屏和 1280×800 桌面；同时用 390×360 短屏检查搜索、音乐库和更新日志弹窗。测试数据包含长名称、长聊天链接和多操作按钮。

核验时记录页面宽度、弹窗边界、按钮尺寸及实际截图。视口仿真不是 iOS Safari、Android 浏览器或实体刘海设备的实机验收；软键盘和真实安全区仍建议在目标设备检查。

上述网页仿真只验证 Web 响应式布局，不代表原生安装包验收；APK 的独立构建及 Actions 配置见 Android APK 文档。不改变开发服务器默认的本机回环监听地址；手机访问应使用已部署的 HTTPS 网页，或由开发者另行明确配置可访问的局域网调试环境。
